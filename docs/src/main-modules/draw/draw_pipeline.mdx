## What is Drawing?

Drawing (also known as :dfn:`rendering`) is writing pixel colors into a buffer from
where they will be delivered to a display panel as pixels. It can mean filling areas
with a color, blending images, or using complex algorithms to, for example, calculate rounded
corners or rotate images.

The following sections cover how LVGL's drawing logic works and how to use it.

## Draw-Pipeline Overview

Modern embedded devices come with a wide variety of solutions to speed up rendering:

- 2D GPUs fill areas and blend images
- 2.5D (Vector graphics) GPUs
- 3D GPUs (e.g. for OpenGL)
- SIMD assembly-level acceleration
- multi-core CPUs
- Software libraries
- and more

To make it possible to utilize such facilities, LVGL hands each drawing to a
:dfn:`Draw Unit` (rendering engine). The drawing functions, such as
<ApiLink name="lv_draw_rect" /> and <ApiLink name="lv_draw_label" />, take a
[Draw Descriptor](/main-modules/draw/draw_descriptors) describing what to draw, and pass it
to the default Draw Unit, or to its fallback if the default can't draw it, before they
return.

This is designed so that it is both flexible and extensible. You can use it to perform
custom rendering with a GPU or replace parts of the built-in software rendering logic to
any extent desired.

Using events, it's also possible to modify the draw descriptors or draw something below or
on top of them as LVGL renders Widgets (see `LV_EVENT_DRAW_DSC_BEGIN` and
`LV_EVENT_DRAW_DSC_END`).

The following sections describe the basic terminology and concepts of rendering.

## Draw Units

A "Draw Unit" (based on <ApiLink name="lv_draw_unit_t" />) is any "logic entity" that can
draw a descriptor. This can be a CPU core, a GPU, a custom rendering library for specific
descriptor types, or any entity capable of performing rendering.

A Draw Unit has a `draw_cbs` table with a draw callback for each descriptor type it can draw
(e.g. `draw_fill_cb`, `draw_label_cb`). Each callback gets the target layer, the clip area,
the descriptor and, for most types, the area to draw.

For a reference implementation of a draw unit, see
[lv_draw_sw.c](https://github.com/lvgl/lvgl/blob/master/src/draw/sw/lv_draw_sw.c).

### Creating Draw Units

During LVGL's initialization (in <ApiLink name="lv_init" />), a list of Draw Units is created
from the enabled built-in draw units. For example, if <ApiLink name="LV_USE_DRAW_SW" /> is
enabled, it will be automatically initialized and used for rendering. The same applies for
<ApiLink name="LV_USE_DRAW_OPENGLES" />, <ApiLink name="LV_USE_DRAW_PXP" />, <ApiLink name="LV_USE_DRAW_SDL" />, or
<ApiLink name="LV_USE_DRAW_VG_LITE" />.

You can also add your own Draw Unit(s) after <ApiLink name="lv_init" /> by calling
<ApiLink name="lv_draw_create_unit" display="lv_draw_create_unit(sizeof(your_draw_unit_t))" />. You also need to
set its `draw_cbs` table (optionally with `can_draw_*_cb` callbacks) and its `fallback`.

For an example of how draw-unit creation and initialization is done, see
<ApiLink name="lv_draw_sw_init" /> in lv_draw_sw.c_ or the other draw units whose `init`
functions are in <ApiLink name="lv_init" />.

### Clip Area

LVGL clips the children widgets to the parent's boundary. To do that, it needs to know
the current clip area when a drawing function is called. The current clip area is the smallest
intersection of all parent clip areas and the widget to be rendered. So, if a widget is
out of its parent at the bottom and only its top part is visible, the clip area will be
that small top part.

The draw callbacks get this clip area as a parameter. Draw units should use it, not the
layer's current clip area, for example, to mask out only a smaller part of an image to be
blended.

<ApiLink name="lv_obj_set_ext_draw_size"/> combined with <ApiLink name="LV_OBJ_FLAG_OVERFLOW_VISIBLE"/>
can be used to increase the widget's clip area, allowing the children to overflow.

## Choosing the Draw Unit

The last created Draw Unit is the default. The built-in Draw Units are created in
<ApiLink name="lv_init" /> from the lowest to the highest priority, so with several GPU
Draw Units enabled, the one with the highest priority draws and the others draw nothing.
Each Draw Unit sets its own `fallback` when it's created: the built-in GPU Draw Units set it to
the software renderer, never to another GPU Draw Unit. Without <ApiLink name="LV_USE_DRAW_SW" />
it's `NULL`, so what the default Draw Unit can't draw isn't drawn.
A Draw Unit that leaves `fallback` `NULL` (e.g. EVE and NanoVG) drops what it can't draw.

When a drawing function is called, the default Draw Unit is asked whether it can draw the
descriptor, through the `can_draw_*_cb` callback for its type in the `draw_cbs` table. If the
callback is `NULL`, the Draw Unit can draw every descriptor of the types it has a draw callback
for. If it can, its draw callback is called. If it can't, the fallback is asked the same way.
If neither can draw it, nothing is drawn and a warning is logged.

The `can_draw_*_cb` callbacks must not change anything, so the same Draw Unit is selected
consistently, depending on the type (and nature) of the drawing, avoiding any possible
screen jitter.

## Draw Counters

With <ApiLink name="LV_USE_DRAW_COUNTERS" /> enabled, LVGL counts per descriptor type how many
descriptors each Draw Unit draws, including those it draws as a fallback, and how many no Draw
Unit can draw. This shows, for example, whether a GPU draws the images or the software renderer
does. A rectangle counts its fill, border and shadow separately, and a refresh in several
areas (e.g. partial rendering) counts each area.

```c
lv_draw_reset_counters();
/* ... draw or refresh ... */

lv_draw_unit_t * unit = lv_draw_unit_get_next(NULL);   /* the default Draw Unit */
while(unit) {
    LV_LOG_USER("%s: %u images", lv_draw_unit_get_name(unit),
                lv_draw_unit_get_draw_count(unit, LV_DRAW_DSC_TYPE_IMAGE));
    unit = lv_draw_unit_get_next(unit);
}
LV_LOG_USER("dropped: %u images", lv_draw_get_dropped_count(LV_DRAW_DSC_TYPE_IMAGE));
```

## Waiting for the Draw Units

A Draw Unit may queue the drawing instead of finishing it before its draw callback returns,
for example in a GPU command list. Such a Draw Unit implements `wait_for_finish_cb`, which
waits until everything it has queued is drawn. LVGL calls it before the fallback draws, and
<ApiLink name="lv_draw_wait_for_finish" /> calls it for every Draw Unit, e.g. before a
rendered area is flushed to the display, a snapshot is returned, or a Canvas layer is
finished.

A Draw Unit that queues copies what it needs from the descriptor: the descriptor, and the
data it points to, are only valid during the draw callback.
