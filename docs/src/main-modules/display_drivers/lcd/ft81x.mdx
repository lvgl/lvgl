## Overview

[EVE](https://brtchip.com/eve/) (Embedded Video Engine) is a family of smart display controllers
from Bridgetek/FTDI --- the FT81x and BT81x parts --- that drive a parallel RGB panel and are
themselves driven over SPI.

This is a **framebuffer** driver: LVGL renders the pixels in software and the driver ships them to
the EVE chip over SPI, using the chip as a plain display. It is the simpler of the two ways LVGL
can use EVE hardware.

<Callout type="tip" title="There is a faster alternative">
An EVE chip can rasterize by itself from high-level drawing commands. The
[EVE renderer](/main-modules/renderers/eve) uses it that way, which offloads drawing entirely and
sends far less data over SPI. Consider it if performance matters — it drives the same chips.
</Callout>

Tested at 32 MHz on an FT812 and at 23 MHz on a BT817.

### Prerequisites

An FT81x or BT81x controller on an SPI bus, plus a GPIO for chip select and one for the chip's
power-down (`PD`) pin. You supply a single callback that performs the SPI operations.

## Configuration

Enable <ApiLink name="LV_USE_FT81X" />.

Everything else, resolution, panel timings, clock source and chip family is passed at runtime
in an <ApiLink name="lv_ft81x_parameters_t" /> rather than configured in LVGL's configuration.

### Panel parameters

| Field | Meaning |
|---|---|
| `hor_res`, `ver_res` | Active display size |
| `hcycle`, `vcycle` | Total clocks per line / lines per screen, including porches |
| `hoffset`, `voffset` | Start of the active line / active screen |
| `hsync0`, `hsync1` | Start and end of the horizontal sync pulse |
| `vsync0`, `vsync1` | Start and end of the vertical sync pulse |
| `swizzle` | FT8xx-to-panel pin order |
| `pclkpol` | Which PCLK edge the panel latches data on |
| `cspread` | When `1`, fewer signals change simultaneously; helps with noise. Reset default is `1` |
| `pclk` | Pixel clock divider — the resulting frequency is 60 MHz / `pclk` |
| `has_crystal` | The board has an external clock crystal |
| `is_bt81x` | The chip is a BT series part rather than an FT |

These are the same values used by `EVE_config.h`-style headers, so an existing configuration for
your panel can be copied across directly.

## Usage

Implement one SPI callback that handles four operations, then create the display with
<ApiLink name="lv_ft81x_create" />. The `user_data` pointer you pass in is retrievable inside the
callback with <ApiLink name="lv_ft81x_get_user_data" />.

```c
#define FB_SIZE             800 * 2 * 50
#define MAX_TRANSFER_SIZE   FB_SIZE

static void spi_cb(lv_display_t * disp, lv_ft81x_spi_operation_t operation, void * data, uint32_t length)
{
    spi_device_handle_t spi = lv_ft81x_get_user_data(disp);
    switch(operation) {
        case LV_FT81X_SPI_OPERATION_CS_ASSERT:
            gpio_set_level(CS_PIN, 0);
            break;
        case LV_FT81X_SPI_OPERATION_CS_DEASSERT:
            gpio_set_level(CS_PIN, 1);
            esp_rom_delay_us(10); /* tiny delay in case a CS_ASSERT immediately follows */
            break;
        case LV_FT81X_SPI_OPERATION_SEND: {
            spi_transaction_t trans = {0};
            while(length) {
                uint32_t sz = length < MAX_TRANSFER_SIZE ? length : MAX_TRANSFER_SIZE;
                trans.length = sz * 8;
                trans.rxlength = 0;
                trans.tx_buffer = data;
                spi_device_polling_transmit(spi, &trans);
                length -= sz;
                data += sz;
            }
            break;
        }
        case LV_FT81X_SPI_OPERATION_RECEIVE: {
            spi_transaction_t trans = {0};
            trans.length = length * 8;
            trans.rxlength = length * 8;
            trans.rx_buffer = data;
            spi_device_polling_transmit(spi, &trans);
            break;
        }
    }
}

int main(void)
{
    /* ... */

    /* Reset the ft81x */
    gpio_set_level(PD_PIN, 0);
    vTaskDelay(6 / portTICK_PERIOD_MS);
    gpio_set_level(PD_PIN, 1);
    vTaskDelay(21 / portTICK_PERIOD_MS);

    /* ... */

    /* Panel timings for a NHD-5.0-800480FT-CxXx-xxx: 800x480 5.0" Newhaven, FT81x.
     * Taken from https://github.com/lvgl/lvgl_esp32_drivers/blob/9fed1cc/lvgl_tft/EVE_config.h */
    #define EVE_VSYNC0  (0L)
    #define EVE_VSYNC1  (3L)
    #define EVE_VOFFSET (32L)
    #define EVE_VCYCLE  (525L)
    #define EVE_HSYNC0  (0L)
    #define EVE_HSYNC1  (48L)
    #define EVE_HOFFSET (88L)
    #define EVE_HCYCLE  (928L)
    #define EVE_PCLKPOL (0L)
    #define EVE_SWIZZLE (0L)
    #define EVE_PCLK    (2L)
    #define EVE_CSPREAD (1L)

    lv_ft81x_parameters_t params = {
        .hor_res = 800,
        .ver_res = 480,

        .hcycle = EVE_HCYCLE,
        .hoffset = EVE_HOFFSET,
        .hsync0 = EVE_HSYNC0,
        .hsync1 = EVE_HSYNC1,
        .vcycle = EVE_VCYCLE,
        .voffset = EVE_VOFFSET,
        .vsync0 = EVE_VSYNC0,
        .vsync1 = EVE_VSYNC1,
        .swizzle = EVE_SWIZZLE,
        .pclkpol = EVE_PCLKPOL,
        .cspread = EVE_CSPREAD,
        .pclk = EVE_PCLK,

        .has_crystal = true,
        .is_bt81x = false
    };

    static uint8_t fb[FB_SIZE] __attribute__((aligned(4)));
    lv_display_t * disp = lv_ft81x_create(&params, fb, FB_SIZE, spi_cb, spi);

    /* ... */
}
```

The `params` struct does not need to be static --- the driver copies what it needs.

Unlike the [MIPI DCS drivers](/main-modules/display_drivers/lcd/gen_mipi), this driver **does**
configure the display for you: it sets <ApiLink name="LV_COLOR_FORMAT_RGB565" /> and installs the
partial buffer you pass in.

## Troubleshooting

### The backlight does not come on, or is the wrong brightness

Change the value of `PWM_DUTY_BACKLIGHT_ON` in `lv_ft81x.c`. The right value varies by board.

### Nothing appears, or the image is unstable

Check the panel timings first --- a wrong `pclk` or cycle value is the usual cause. Then lower the
SPI clock: the driver has been verified at 32 MHz on an FT812 and 23 MHz on a BT817, and some
boards need less.

## Support

| Capability | Value |
|---|---|
| Hardware | FT81x and BT81x EVE controllers |
| Bus | SPI. DSPI and QSPI may not work currently |
| Rotation | Not supported |
| Runtime resolution change | No |
| Runtime color format change | No |
| Color formats | RGB565, set by the driver |
| Multiple displays / windows | One per controller |
| Hardware acceleration | None in this driver — see the [EVE renderer](/main-modules/renderers/eve) |
| Render mode | Partial, single buffer only |
| Input | None. EVE's touch engine is not used by this driver |
