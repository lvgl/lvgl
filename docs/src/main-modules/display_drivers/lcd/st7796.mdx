## Overview

The [ST7796S](https://www.buydisplay.com/download/ic/ST7796S.pdf) is a single-chip controller/driver for 262K-color, graphic type
TFT-LCD.  It consists of 960 source lines and 480 gate lines driving circuits.  The ST7796S is
capable of connecting directly to an external microprocessor, and accepts 8-bit/9-bit/16-bit/18-bit
parallel interface, SPI, and the ST7796S also provides MIPI interface.  Display data can be stored
in the on-chip display data RAM of 320x480x18 bits.  It can perform display data RAM
read-/write-operation with no external clock to minimize power consumption.  In addition, because
of the integrated power supply circuit necessary to drive liquid crystal; it is possible to make a
display system with fewest components.

The ST7796 LCD controller
[driver](https://github.com/lvgl/lvgl/tree/master/src/drivers/display/st7796) is
platform-agnostic and built on the
[generic MIPI DCS driver](/main-modules/display_drivers/lcd/gen_mipi). It implements display
initialization, supports display rotation and implements the display flush callback. You implement
only two platform-specific functions to send a command or pixel data to the controller over SPI or a parallel bus.
Typically these are implemented by calling the appropriate SDK library functions for your platform.

### Prerequisites

None. You supply the two bus transfer functions, so no third-party library is involved.

## Configuration

Enable <ApiLink name="LV_USE_ST7796" />.

### Create flags

The `flags` argument configures panel orientation and color handling:
<ApiLink name="LV_LCD_FLAG_NONE" />, <ApiLink name="LV_LCD_FLAG_MIRROR_X" />,
<ApiLink name="LV_LCD_FLAG_MIRROR_Y" />, <ApiLink name="LV_LCD_FLAG_BGR" /> and
<ApiLink name="LV_LCD_FLAG_RGB666" />, ORed together. See
[Create flags](/main-modules/display_drivers/lcd/gen_mipi#create-flags) for what each one does.

## Usage

### The two transfer functions

```c
/* Send short command to the LCD. This function shall wait until the transaction finishes. */
void my_lcd_send_cmd(lv_display_t * disp, const uint8_t * cmd, size_t cmd_size,
                     const uint8_t * param, size_t param_size)
{
    ...
}

/* Send large array of pixel data to the LCD. If necessary, this function has to
 * do the byte-swapping. This function can do the transfer in the background. */
void my_lcd_send_color(lv_display_t * disp, const uint8_t * cmd, size_t cmd_size,
                       uint8_t * param, size_t param_size)
{
    ...
}
```

`my_lcd_send_cmd` must block until the transaction has finished. `my_lcd_send_color` should use DMA
and may return before the transfer completes --- but then **you** must call
<ApiLink name="lv_display_flush_ready" /> when it does, usually from the transfer-complete
interrupt. See [Usage](/main-modules/display_drivers/lcd/gen_mipi#usage) on the generic MIPI page
for the full contract, including how to avoid overlapping a command with a running transfer.

### Creating the display

```c
lv_display_t * lv_st7796_create(uint32_t hor_res, uint32_t ver_res, lv_lcd_flag_t flags,
                                lv_st7796_send_cmd_cb_t send_cmd_cb,
                                lv_st7796_send_color_cb_t send_color_cb);
```

<Callout type="warn" title="You must provide the draw buffers">
<ApiLink name="lv_st7796_create" /> does not allocate any draw buffers. Set up your own and assign
them with <ApiLink name="lv_display_set_buffers" /> — see
[Draw Buffer(s)](/main-modules/display/setup#draw-buffers). Without them LVGL cannot operate on
the display.

Setting the color format is also recommended — see
[Color Format](/main-modules/display/color_format).
</Callout>

### Runtime API

| Function | Purpose |
|---|---|
| <ApiLink name="lv_st7796_set_gap" /> | Offset of the (0,0) pixel in the controller's GRAM |
| <ApiLink name="lv_st7796_set_invert" /> | Invert the displayed colors |
| <ApiLink name="lv_st7796_set_gamma_curve" /> | Select one of the predefined gamma curves |
| <ApiLink name="lv_st7796_send_cmd_list" /> | Send a panel-specific init sequence; see [Custom command lists](/main-modules/display_drivers/lcd/gen_mipi#custom-command-lists) |

Rotation goes through the standard <ApiLink name="lv_display_set_rotation" /> --- the driver
handles it in hardware by rewriting the controller's address mode.

## Support

| Capability | Value |
|---|---|
| Hardware | ST7796S, typically 320x480 panels |
| Bus | SPI or 8-/9-/16-/18-bit parallel — you provide the transfer functions. The chip's MIPI DSI interface is not usable through this driver |
| Rotation | Hardware, via the controller's address mode |
| Runtime resolution change | Yes |
| Runtime color format change | No |
| Color formats | RGB565, or RGB666 with `LV_LCD_FLAG_RGB666`. Set the LVGL color format yourself |
| Multiple displays / windows | Yes — one per controller |
| Hardware acceleration | None |
| Render mode | Partial — you allocate the buffers |
| Input | None. Pair with your touch controller's driver |
