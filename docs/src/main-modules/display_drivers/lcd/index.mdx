## Overview

These drivers talk to a **display controller IC on the panel** --- an ST7789, ILI9341 and so on
--- over SPI, I8080 parallel, or MIPI DSI. The controller holds its own framebuffer, so LVGL
renders into a small partial buffer and the driver pushes each flushed area out over the bus.

This is the usual arrangement on MCUs with a small display. Contrast it with the
[SoC display controllers](/main-modules/display_drivers/overview#soc-display-controllers), which
are peripherals inside the chip driving a raw RGB panel.

## Which Driver?

| Your panel | Use |
|---|---|
| Speaks MIPI DCS, or is not listed here | **[Generic MIPI](/main-modules/display_drivers/lcd/gen_mipi)** — supply the init commands from the datasheet |
| ST7735 / ST7735S | **[ST7735](/main-modules/display_drivers/lcd/st7735)** |
| ST7789 | **[ST7789](/main-modules/display_drivers/lcd/st7789)** |
| ST7796 / ST7796S | **[ST7796](/main-modules/display_drivers/lcd/st7796)** |
| ILI9341 | **[ILI9341](/main-modules/display_drivers/lcd/ili9341)** |
| NV3007 | **[NV3007](/main-modules/display_drivers/lcd/nv3007)** |
| An EVE (FT81x / BT81x) smart controller | **[EVE FT81x](/main-modules/display_drivers/lcd/ft81x)** |
| Already configured for LovyanGFX | **[LovyanGFX](/main-modules/display_drivers/lcd/lovyan_gfx)** |
| Already configured for TFT_eSPI | **[TFT_eSPI](/main-modules/display_drivers/lcd/tft_espi)** |

<Callout type="tip" title="Start with Generic MIPI">
The ST77xx, ILI9341 and NV3007 drivers are all thin specializations of the
[generic MIPI DCS driver](/main-modules/display_drivers/lcd/gen_mipi). If your controller is not
listed but its datasheet shows standard DCS commands, the generic driver will very likely drive it
with the right init sequence — no new driver needed.
</Callout>

<Callout type="info" title="EVE is a special case">
An [EVE](/main-modules/display_drivers/lcd/ft81x) controller is not just a framebuffer — it
accepts high-level drawing commands and rasterizes them itself. It can therefore be used as a
[renderer](/main-modules/renderers/eve) instead of a plain display driver, which offloads drawing
entirely. The framebuffer-mode driver here is the simpler of the two options.
</Callout>

## Common Ground

All of these drivers:

- render in <ApiLink name="LV_DISPLAY_RENDER_MODE_PARTIAL" /> mode, so the draw buffer can be much
  smaller than the screen
- need you to supply the bus transfer functions (SPI/I8080 send-command and send-color), because
  LVGL does not own your platform's peripheral drivers
- are display-only — pair them with an [input driver](/main-modules/input_drivers) or your touch
  controller's own driver
