## Overview

[TFT_eSPI](https://github.com/Bodmer/TFT_eSPI) is a widely used Arduino display library that
supports a long list of SPI display controllers. This LVGL driver is a thin adapter over it: LVGL
renders into a buffer, and the driver pushes it out with TFT_eSPI's `pushColors()`.

Its value is compatibility. If you already have a working TFT_eSPI setup, a board definition,
pin mapping and panel type, this driver reuses all of it, and you do not have to reproduce that
configuration for one of LVGL's [native LCD drivers](/main-modules/display_drivers/lcd).

<Callout type="tip">
If you are starting a new project and your controller has a native LVGL driver
([ST7789](/main-modules/display_drivers/lcd/st7789),
[ILI9341](/main-modules/display_drivers/lcd/ili9341),
[ST7796](/main-modules/display_drivers/lcd/st7796) and so on), prefer it. It needs no third-party
library and is configured entirely from LVGL.
</Callout>

### Prerequisites

The TFT_eSPI library must be available in the build, and configured for your panel, normally
through its `User_Setup.h` or the equivalent build flags. This is a C++ driver, so the project
must compile C++.

## Configuration

Enable <ApiLink name="LV_USE_TFT_ESPI" />.

```c
#define LV_USE_TFT_ESPI 1
```

The panel type, pins, SPI frequency and color order are **not** LVGL settings. The driver calls
TFT_eSPI's `begin()`, which reads them from TFT_eSPI's own configuration.

## Usage

Create the display with <ApiLink name="lv_tft_espi_create" />, passing the resolution and a draw
buffer.

```c
#define HOR_RES 240
#define VER_RES 320

/* Partial buffer, 1/10th of the screen */
static uint8_t buf[HOR_RES * VER_RES / 10 * 2];

lv_display_t * disp = lv_tft_espi_create(HOR_RES, VER_RES, buf, sizeof(buf));
```

The driver initializes TFT_eSPI itself, so no `tft.begin()` call of your own is needed.

The buffer is used in <ApiLink name="LV_DISPLAY_RENDER_MODE_PARTIAL" /> mode, so it can be much
smaller than the screen. See [Setting Up Your Display](/main-modules/display/setup#draw-buffers)
for how to size it.

Rotation is forwarded to the panel: calling <ApiLink name="lv_display_set_rotation" /> translates
into a TFT_eSPI `setRotation()` call.

## Support

| Capability | Value |
|---|---|
| Rotation | Hardware, via TFT_eSPI `setRotation()` |
| Runtime resolution change | No |
| Runtime color format change | No |
| Color formats | RGB565 |
| Multiple displays / windows | One per TFT_eSPI instance |
| Hardware acceleration | None |
| Render mode | Partial |
| Input | None. Pair with a touch driver of your own |
