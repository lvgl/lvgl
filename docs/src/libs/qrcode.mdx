The [QR-Code-generator library](https://github.com/nayuki/QR-Code-generator) by
[nayuki](https://github.com/nayuki) is a 3rd-party library that generates QR-Code
bitmaps.

The lv_qrcode LVGL extension is an interface to that library which implements a custom
Widget that generates and displays QR Codes using the library.

## Usage

<LvglExample name="lv_example_qrcode_basic" path="libs/qrcode/qrcode_basic/lv_example_qrcode_basic" />

Enable <ApiLink name="LV_USE_QRCODE" /> in `lv_conf.h` by setting its value to `1`.

Use <ApiLink name="lv_qrcode_create" /> to create the QR-Code Widget. Then set the
payload with <ApiLink name="lv_qrcode_set_text" /> for a NUL terminated string, or
<ApiLink name="lv_qrcode_set_data" /> for binary data.

Use <ApiLink name="lv_qrcode_set_size" />, <ApiLink name="lv_qrcode_set_dark_color" />,
<ApiLink name="lv_qrcode_set_light_color" /> and <ApiLink name="lv_qrcode_set_quiet_zone" />
to set the appearance. You can call them in any order, before or after you set the
payload. The Widget keeps a copy of the payload and encodes it again when necessary.

### Update mode

A change of the size or the quiet zone encodes the payload again. By default, this
occurs in the setter, so each change encodes the bitmap one time.
<ApiLink name="lv_qrcode_set_update_mode" /> sets the mode:

- `LV_QRCODE_UPDATE_MODE_IMMEDIATE` (the default) encodes in the setter.
- `LV_QRCODE_UPDATE_MODE_DEFERRED` only marks the bitmap as out of date. Call
  <ApiLink name="lv_qrcode_render" /> one time after all the changes.

```c
lv_qrcode_set_update_mode(qr, LV_QRCODE_UPDATE_MODE_DEFERRED);
lv_qrcode_set_size(qr, 200);
lv_qrcode_set_quiet_zone(qr, true);

lv_qrcode_render(qr);   /* encode one time and get the result */
```

<ApiLink name="lv_qrcode_render" /> encodes the payload that the Widget keeps. You do
not give the payload again.

If you do not call `lv_qrcode_render()`, the next redraw encodes the bitmap and logs a
warning. The encode time then adds to that refresh. If the encode fails, no function
returns the error.

A switch back to `LV_QRCODE_UPDATE_MODE_IMMEDIATE` also encodes a bitmap that is out of
date and logs a warning. <ApiLink name="lv_qrcode_set_update_mode" /> returns `void`, so
it cannot return the result. To get the result, call `lv_qrcode_render()` first:

```c
lv_qrcode_render(qr);                                            /* returns the result */
lv_qrcode_set_update_mode(qr, LV_QRCODE_UPDATE_MODE_IMMEDIATE);  /* nothing to encode */
```

The mode has no effect on the payload setters. <ApiLink name="lv_qrcode_set_text" /> and
<ApiLink name="lv_qrcode_set_data" /> always encode immediately and return the result.
The mode also has no effect on the colors. A color change only writes the palette.

### Detecting a failed encode

The payload setters and `lv_qrcode_render()` return the encode result. Other encodes
cannot return a result. `lv_qrcode_set_size()` and `lv_qrcode_set_quiet_zone()` return
`void`, and in deferred mode the redraw does the encode. For example, if you make the
object too small for the payload, no function returns an error.
Use <ApiLink name="lv_qrcode_is_render_valid" /> to find these failures:

```c
lv_qrcode_set_size(qr, 10);   /* too small for this payload */
if(!lv_qrcode_is_render_valid(qr)) {
    /* the bitmap is blank; set a larger size */
}
```

`lv_qrcode_is_render_valid()` returns `false` for a new QR code with no payload. Each
change of the size, the quiet zone or the payload sets it to `true` before the encode. Thus `true`
means that no encode failed. It does not mean that the bitmap is up to date. In deferred
mode, it is also `true` while an encode is pending.

After a failed encode, the bitmap stays marked as out of date. The Widget does not retry
the encode on each redraw. The next change of the size, the quiet zone or the payload
starts a new attempt.

The Widget does not log an encode failure if the caller can get the result. The payload
setters and `lv_qrcode_render()` return it. For the property setters, the result is
available from `lv_qrcode_is_render_valid()`. Thus a size animation through values that
are all too small logs nothing. Only two encodes log a failure: the encode in the redraw,
and the encode in the switch to immediate mode. No caller can get their result.

### Reading the payload back

<ApiLink name="lv_qrcode_get_text" /> returns the string set with
`lv_qrcode_set_text()`. It returns `NULL` if the payload was set with
`lv_qrcode_set_data()`.

<ApiLink name="lv_qrcode_get_data" /> copies the payload of either kind into a buffer
and returns its full length in bytes. If the return value is larger than the buffer
size, the copy was truncated. Pass a `NULL` buffer to get only the length. The length of
a text payload does not include the NUL terminator.

## Notes

- A QR Code with less data has fewer modules. The Widget scales the modules by an
  integer value to fit the size. If the size is too small for one pixel per module, the
  encode fails with `LV_RESULT_INVALID`. The quiet zone needs more space, so a size that
  is correct without it can be too small with it.
- A color change (dark or light) only writes the palette. It does not encode the QR Code
  again.
