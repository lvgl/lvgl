The LVGL Barcode utility enables you to generate Code-128 bar codes.  It uses the
[code128](https://github.com/fhunleth/code128) library by
[fhunleth](https://github.com/fhunleth).

## Usage

Set <ApiLink name="LV_USE_BARCODE" /> to `1` in `lv_conf.h`.

Use <ApiLink name="lv_barcode_create" /> to create a barcode object, and use
<ApiLink name="lv_barcode_set_text" /> to set the text to encode.
<ApiLink name="lv_barcode_get_text" /> reads it back.

Call <ApiLink name="lv_barcode_set_scale" /> to adjust scaling,
call <ApiLink name="lv_barcode_set_dark_color" /> and <ApiLink name="lv_barcode_set_light_color" />
adjust colors.  Call <ApiLink name="lv_barcode_set_direction" /> to set the bar code's
orientation.

By default, <ApiLink name="LV_BARCODE_ENCODING_CODE128_GS1" /> encoding is used
and strips `[FCN1]` and spaces. Optionally use
<ApiLink name="lv_barcode_set_encoding" /> to set
<ApiLink name="LV_BARCODE_ENCODING_CODE128_RAW" />.

You can call these functions in any order, before or after you set the text. The Widget
keeps a copy of the text, which uses its length in bytes. A change of the scale, the
direction, the tiled mode or the encoding generates the bars again. A resize also
generates the bars again.

### Update mode

<ApiLink name="lv_barcode_set_update_mode" /> sets when a change generates the bars:

- `LV_BARCODE_UPDATE_MODE_IMMEDIATE` (the default) generates the bars in the setter.
- `LV_BARCODE_UPDATE_MODE_DEFERRED` only marks the bars as out of date. Many changes then
  cause only one generation. Call <ApiLink name="lv_barcode_render" /> one time after all
  the changes. It generates the bars from the stored text and returns the result.

```c
lv_barcode_set_update_mode(barcode, LV_BARCODE_UPDATE_MODE_DEFERRED);
lv_barcode_set_scale(barcode, 2);
lv_barcode_set_direction(barcode, LV_DIR_VER);

lv_barcode_render(barcode);   /* generate one time and get the result */
```

If you do not call `lv_barcode_render()`, the next redraw generates the bars and logs a
warning. The time for this then adds to that refresh. If the generation fails, no function
returns the error.

Notes about deferred mode:

- The setter resizes the canvas in both modes, because the redraw cannot reallocate it.
  Only the fill of the bars is deferred.
- <ApiLink name="lv_barcode_set_text" /> also obeys the mode. In deferred mode, its return
  value is only the result of the resize.

A switch back to `LV_BARCODE_UPDATE_MODE_IMMEDIATE` also generates bars that are out of
date and logs a warning. <ApiLink name="lv_barcode_set_update_mode" /> returns `void`,
so it cannot return the result. To get the result, call `lv_barcode_render()` first.

### Detecting a failed generation

<ApiLink name="lv_barcode_render" /> returns its result. In immediate mode,
<ApiLink name="lv_barcode_set_text" /> also returns its result. Other generations cannot
return a result. The property setters return `void`, an event handler does the resize,
and in deferred mode the redraw fills the bars.
Use <ApiLink name="lv_barcode_is_render_valid" /> to find these failures:

```c
lv_obj_set_height(barcode, 0);   /* no space for a horizontal barcode */
if(!lv_barcode_is_render_valid(barcode)) {
    /* the bitmap is blank; set a height */
}
```

`lv_barcode_is_render_valid()` returns `false` for a new barcode with no text. The Widget
does not retry a failed generation on each redraw. A change of the text, the scale, the
direction, the tiled mode or the encoding, or a resize, sets the flag to `true` before the
new attempt. A color change does not. Thus `true` means that no generation failed. It does not mean that
the bitmap is up to date. In deferred mode, it is also `true` while a generation is
pending.

## Notes

- It is best not to manually set the width of the barcode, because when
   the width of the Widget is lower than the width of the barcode, the
   display will be incomplete due to truncation.
- A horizontal barcode has the height of the Widget, and a vertical barcode has its
   width. You must set that dimension. Before you set it, the Widget cannot generate the
   bars. The Widget keeps the text, so the barcode shows when the Widget gets a size.
- The scale adjustment can only be an integer multiple, for example,
   <ApiLink name="lv_barcode_set_scale" display="lv_barcode_set_scale(barcode, 2)" /> means 2x scaling.
- The direction setting can be <ApiLink name="LV_DIR_HOR" /> or <ApiLink name="LV_DIR_VER" />.
- A color change (dark or light) only writes the palette. It does not generate the
   bars again.
