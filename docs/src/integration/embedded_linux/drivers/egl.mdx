## Overview

**EGL** (Embedded-System Graphics Library) is the platform layer that binds OpenGL ES to a native
windowing system. It creates the GL context, allocates the surface the GPU renders into, and hands the
finished frame to the platform. It sits lower than GLFW and is tied more closely to the platform's own
drivers, which is why it is the path LVGL uses for GPU rendering on embedded Linux.

EGL is not a driver you select on its own. It is the hardware-accelerated backend of the drivers that
have one:

- [DRM](/integration/embedded_linux/drivers/drm) for rendering straight to a display
- [Wayland](/integration/embedded_linux/drivers/wayland) for rendering under a compositor
- [SDL](/integration/pc/sdl) for a desktop window

## Configuration

There is nothing to enable directly. <ApiLink name="LV_USE_EGL" /> is selected for you based on the drivers
you enable.

EGL and OpenGL ES are loaded at runtime with `dlopen` (`libEGL.so` and `libGLESv2.so`), so enabling
<ApiLink name="LV_USE_EGL" /> adds no link-time dependency and nothing appears for it in LVGL's dependency
resolution. Both libraries must be present on the target at run time.

<Callout type="info">
<ApiLink name="LV_USE_GLFW" /> depends on <ApiLink name="LV_USE_EGL" /> being off, the two windowing
paths are mutually exclusive and cannot be built into the same binary.
</Callout>
