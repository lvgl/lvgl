# ChibiOS/RT

Select `LV_USE_OS LV_OS_CHIBIOS` to use ChibiOS/RT threads, recursive mutexes,
and binary semaphore events. This backend adapts the OSAL portion of
[PR #8198](https://github.com/lvgl/lvgl/pull/8198) to the current LVGL OSAL.

Enable these options in `chconf.h`:

```c
#define CH_CFG_USE_MUTEXES TRUE
#define CH_CFG_USE_MUTEXES_RECURSIVE TRUE
#define CH_CFG_USE_SEMAPHORES TRUE
#define CH_CFG_USE_DYNAMIC TRUE
#define CH_CFG_USE_HEAP TRUE
#define CH_CFG_USE_WAITEXIT TRUE
```

LVGL stack sizes are stack bytes. The backend adds the ChibiOS thread object
and saved-context overhead when allocating a working area. Thread deletion
joins the worker; arrange for its callback to return before deleting it.

Initialize mutexes and synchronization objects explicitly in thread context
before sharing them with another thread or an ISR. A synchronization object
retains one signal sent before a wait. Each signal releases one blocked waiter;
multiple signals with no waiter coalesce into one pending event. Deleting an
event releases blocked waiters with `LV_RESULT_INVALID`.

`lv_thread_sync_signal_isr()` uses the ChibiOS ISR locking APIs. ChibiOS mutexes
cannot be owned by an ISR, so `lv_mutex_lock_isr()` returns `LV_RESULT_INVALID`.
Keep GUI operations in thread context.

With `LV_USE_SYSMON`, also enable `CH_DBG_STATISTICS` and `CH_CFG_USE_TM`, and
retain the idle thread. The CPU monitor samples the current core's idle-thread
runtime under the kernel lock and compares it with elapsed realtime-counter
cycles. It includes DMA sleeps as idle time and needs no extra sampling thread
or application hooks. Sample at least once per realtime-counter wrap (about
10.7 seconds at 400 MHz); the default 300 ms sysmon period satisfies this.

This OS backend does not change the display transport or enable a graphics
accelerator. SPI displays continue to use their SPI flush driver.
