NXP has integrated LVGL into the MCUXpresso SDK packages for several of our
microcontrollers as an optional software component, allowing easy evaluation and
migration into your product design. LVGL is a free and open-source embedded
graphic library with features that enable you to create embedded GUIs with
intuitive graphical elements, beautiful visual effects and a low memory
footprint. The complete graphic framework includes a variety of widgets for you
to use in the creation of your GUI, and supports more advanced functions such as
animations and anti-aliasing.

LVGL enables graphics in our free GUI Guider UI tool. It's available for use
with NXP's general purpose and crossover microcontrollers, providing developers
with a tool for creating complete, high quality GUI applications with LVGL.

## Creating a New Project with LVGL

[Download an SDK for a supported board](https://www.nxp.com/design/software/embedded-software/littlevgl-open-source-graphics-library:LITTLEVGL-OPEN-SOURCE-GRAPHICS-LIBRARY?&tid=vanLITTLEVGL-OPEN-SOURCE-GRAPHICS-LIBRARY)
today and get started with your next GUI application. It comes fully configured
with LVGL (and with PXP/G2D support if the modules are present), no
additional integration work is required.

## Drivers and Renderers

The NXP-specific pieces LVGL supports are documented with the rest of the drivers and renderers:

| What you need | Use |
|---|---|
| Display output over RGB or MIPI-DSI | **[NXP eLCDIF](/main-modules/display_drivers/nxp_elcdif)** |
| GPU on i.MX RT (MCU) | **[PXP](/main-modules/renderers/pxp)** |
| Vector graphics on i.MX RT with a Verisilicon GPU | **[VG-Lite](/main-modules/renderers/vg_lite)** |
| GPU on i.MX (MPU) | **[G2D](/main-modules/renderers/g2d)** |
| Display on i.MX running Linux | **[DRM](/main-modules/display_drivers/drm)** or **[Wayland](/main-modules/display_drivers/wayland)** — Wayland has a G2D backend |
| Touch and keyboard on i.MX running Linux | **[evdev](/main-modules/input_drivers/evdev)** or **[libinput](/main-modules/input_drivers/libinput)** |

### On i.MX RT (MCU) platforms

Acceleration is done by the NXP PXP (PiXel Pipeline) and/or the Verisilicon GPU through an API
named VG-Lite. Each accelerator has its own context, which allows them to be used individually as
well as simultaneously (in LVGL multithreading mode).

<Callout type="info">
The NXP-specific VGLite draw unit was removed in LVGL v9.4. Use the generic
[VG-Lite](/main-modules/renderers/vg_lite) draw unit (<ApiLink name="LV_USE_DRAW_VG_LITE" />)
instead — it talks to the same Verisilicon VG-Lite API.
</Callout>

### On i.MX (MPU) platforms

Acceleration is done, hardware independently, by the NXP G2D library. It has its own context, so
it can be used individually as well as simultaneously with the CPU (in LVGL multithreading mode).

i.MX MPUs normally run Linux, so the display and input side is the standard Linux stack. See
[Embedded Linux](/integration/embedded_linux).
